# naming_schema (Data Source)

The naming schema resolved from the [provider's](../index.md) configuration: the bundled convention with any override merged over it.

Useful for inspecting what a convention actually resolves to, and for rendering a name in HCL instead of through [`naming_name`](name.md).

~> **Note** In releases up to `v0.0.2` this was a *resource* (`resource "naming_schema"`), which also held a random UUID in state. It is now a data source, and the unique id comes from the provider's `random_seed` instead. See [Migrating](#migrating-from-the-naming_schema-resource) below.

## Example Usage

```terraform
# The naming schema resolved from the provider's configuration - the bundled
# convention with any override merged over it.
data "naming_schema" "this" {}

output "storage_account_abbreviation" {
  value = data.naming_schema.this.abbreviations.Azure["Microsoft.Storage/storageAccounts::default"]
  # "st"
}

output "storage_account_pattern" {
  value = data.naming_schema.this.patterns.Azure["Microsoft.Storage/storageAccounts"].default
  # "<TYPE><LOCATION><ENVIRONMENT><NAME><INDEX;%02s>"
}

output "index_modifier" {
  value = data.naming_schema.this.index_modifier
  # 1, so rendered indices start at 01
}
```

## Schema

### Read-Only

- `abbreviations` (Dynamic) The merged abbreviations table, keyed `<provider>` then `"<Namespace>/<Type>::<kind>"`.
- `default_parameters` (Dynamic) The convention's default parameters with the provider's `parameters` layered on top.
- `enforce_lower_case` (Dynamic) The resolved lower-casing settings.
- `index_modifier` (Dynamic) The resolved index offset (e.g. `1`, so rendered indices start at `01`).
- `mappings` (Dynamic) The merged mappings table (e.g. location and environment shortnames).
- `patterns` (Dynamic) The merged patterns table.
- `unique_id` (String) The UUID that `<UNIQUE_ID_n>` renders from, derived from the provider's `random_seed`. Empty when no seed is configured.

## Why the tables are dynamic

The YAML mixes value types at the same level by design — `patterns` holds a string under `default` next to objects under `Azure` and `AzureAD`, and `enforce_lower_case` holds a bool next to per-provider objects. A typed attribute cannot express that, so the tables are returned as dynamic values and indexed the same way they are written in YAML.

## Migrating from the `naming_schema` resource

The attributes are unchanged apart from the unique id, so the move is `resource` → `data` plus dropping the inputs, which now live on the provider:

```hcl
# before (<= v0.0.2)
resource "naming_schema" "this" {
  convention  = "default"
  naming      = "${path.module}/naming.yaml"
  random_seed = "myapp-prod"
  parameters  = { location = "westeurope" }
}
# naming_schema.this.random.uuid

# after
provider "naming" {
  convention  = "default"
  naming      = "${path.module}/naming.yaml"
  random_seed = "myapp-prod"
  parameters  = { location = "westeurope" }
}

data "naming_schema" "this" {}
# data.naming_schema.this.unique_id
```

- `random.uuid` and `id` are replaced by `unique_id`.
- An unseeded random id is gone: the id is now always derived from `random_seed`, which is what makes it reproducible without state. Set a seed if a pattern you use contains `<UNIQUE_ID_n>`.
- Remove the old resource from state with `terraform state rm naming_schema.this`; it managed nothing outside Terraform, so nothing is destroyed.
