# naming_name (Data Source)

Renders one or more resource names from the naming schema configured on the [provider](../index.md).

This is a data source rather than a resource because rendering is pure: the same schema and the same arguments always produce the same names, so there is nothing to persist and nothing to drift.

## Example Usage

```terraform
# A single name.
data "naming_name" "storage_account" {
  resource = "Azure::Microsoft.Storage/storageAccounts"
}

# A variant of the same resource type: kind picks a different abbreviation
# ("disks::os" => osdisk, "disks::data" => disk) and may pick its own pattern.
data "naming_name" "os_disk" {
  resource = "Azure::Microsoft.Compute/disks::os"
}

# naming_id selects a named variant and takes precedence over kind.
data "naming_name" "vm_storage_account" {
  resource  = "Azure::Microsoft.Storage/storageAccounts::vm"
  naming_id = "vm_pattern"
}

# A set of sequentially numbered names. count is how many to render, start
# only shifts the first index.
data "naming_name" "virtual_networks" {
  resource = "Azure::Microsoft.Network/virtualNetworks"

  index = {
    start = 0
    count = 3
  }
}

# Per-call parameters are layered over the provider's.
data "naming_name" "app_service" {
  resource = "Azure::Microsoft.Web/sites"

  parameters = {
    name    = "frontend"
    subname = "api"
  }
}
```

## Schema

### Required

- `resource` (String) The resource to name, as `"<Provider>::<Namespace>/<Type>[::<kind>]"` - e.g. `"Azure::Microsoft.Storage/storageAccounts"` or `"Azure::Microsoft.Compute/disks::os"`. The optional `kind` selects a variant of the same type and defaults to `default`.

### Optional

- `index` (Attributes) The index range to render. Omitted, a single name is rendered at index `start = 0`. (see [below for nested schema](#nestedatt--index))
- `naming_id` (String) Selects a named variant of the pattern and abbreviation. Takes precedence over the resource's `kind`.
- `parameters` (Map of String) Parameters for this call, layered on top of the provider's `parameters` and the convention's `default_parameters`.

### Read-Only

- `at_index` (List of String) Every rendered name, in index order - `index.count` of them.
- `by_index` (List of String) Alias for `at_index`.
- `name` (String) The first rendered name.
- `result` (String) Alias for `name`.

<a id="nestedatt--index"></a>
### Nested Schema for `index`

Optional:

- `count` (Number) How many names to render. Defaults to `1`.
- `start` (Number) The first index. Defaults to `0`, which the convention's `index_modifier` shifts (so the first name is numbered `01` by default).

## Index Behaviour

`index.count` is **how many names** to render; `index.start` only shifts the first index. The convention's `index_modifier` then shifts every index on top of that — with the bundled `index_modifier: 1`, `{ start = 2, count = 5 }` renders five names numbered `03` through `07`.

A parameter named `index` overrides `index.start`:

```hcl
data "naming_name" "vm" {
  resource   = "Azure::Microsoft.Compute/virtualMachines"
  parameters = { index = 7 }
}
# -> ...-08 with index_modifier = 1
```
