# naming Provider

Schema-driven Azure resource naming, following Microsoft's [Cloud Adoption Framework (CAF)](https://learn.microsoft.com/en-us/azure/cloud-adoption-framework/ready/azure-best-practices/resource-abbreviations) conventions.

The naming convention — patterns, abbreviations, mappings and settings — is declared **once** on the provider, as a bundled convention plus an optional YAML override. The [`naming_name`](data-sources/name.md) data source then renders names from it, and [`naming_schema`](data-sources/schema.md) exposes the resolved tables for inspection.

This replaces the two Terraform modules that previously did the same job (`LemurDaniel/naming-schema/random` for resolving the schema and `LemurDaniel/naming/random` for rendering names) with a single provider, with no `module` blocks or output plumbing in between. Rendered names are unchanged: the provider's engine is a port of the modules' logic and is tested against their fixtures.

## Example Usage

```terraform
terraform {
  required_providers {
    naming = {
      source  = "LemurDaniel/naming"
      version = "~> 1.0"
    }
  }
}

provider "naming" {
  convention = "default"
  naming     = "${path.module}/naming.yaml"

  parameters = {
    location    = "westeurope"
    environment = "development"
    name        = "myapp"
  }
}

data "naming_name" "storage_account" {
  resource = "Azure::Microsoft.Storage/storageAccounts"
}

resource "azurerm_storage_account" "this" {
  name = data.naming_name.storage_account.name
  # ...
}
```

Everything resolves during `terraform plan` — the provider reads embedded YAML and merges it in memory, with no API calls and nothing in state.

## Schema

### Optional

- `convention` (String) Name of the bundled convention to load (e.g. `"default"`). Defaults to `"default"`.
- `naming` (String) Path to a YAML file that partially overrides the bundled convention (e.g. `"${path.module}/naming.yaml"`). Every table is merged per key with your value winning, so an override may set a single abbreviation or pattern without restating the block around it.
- `parameters` (Map of String) Runtime parameters (`location`, `environment`, `name`, ...) that patterns render from. Layered on top of the convention's `default_parameters`, and overridable per call on the data source.
- `random_seed` (String) Seed for the `<UNIQUE_ID_n>` pattern token. The same seed always resolves to the same id, so names stay stable across plans and applies without any state. Required only if a pattern you use actually contains the token.

## Merge Semantics

An override file set through `naming` is merged **per key, with your value winning**. Keys it does not mention keep the bundled convention's value, so a single abbreviation or a single pattern can be changed without restating the block around it:

```yaml
# naming.yaml - changes one abbreviation and one pattern, keeps everything else
abbreviations:
  Azure:
    Microsoft.Storage/storageAccounts::default: mystg

patterns:
  Azure:
    Microsoft.Compute/disks:
      os: "<TYPE>-<NAME>-<ENVIRONMENT>"
```

This holds at every level, including `patterns`, which is three levels deep (global string, provider string, per-type object of kind → pattern). `index_modifier` and a scalar `enforce_lower_case` are replaced outright when set; a nested `enforce_lower_case` block is merged like the other tables.

`default_parameters` has three layers, each winning over the one before it: the bundled convention, then the override file, then the provider's `parameters`.

## Naming Convention YAML

The bundled `"default"` convention is embedded in the provider binary; its source lives at [`internal/schemaengine/convention/default.naming.yaml`](https://github.com/LemurDaniel/terraform-provider-naming/blob/master/internal/schemaengine/convention/default.naming.yaml). It has these top-level keys:

- **`index_modifier`** — global index offset (`1`, so rendered indices start at `01`).
- **`enforce_lower_case`** — whether finished names are lower-cased, as a global default plus optional per-provider and per-resource-type overrides.
- **`patterns`** — the pattern strings, falling back up the hierarchy to a global default.
- **`abbreviations`** — keyed `<provider>` → `"<Namespace>/<Type>::<kind>"` → abbreviation, e.g. `Azure."Microsoft.Compute/disks::os": osdisk`. The `::<kind>` suffix is how one resource type carries several abbreviations.
- **`mappings`** — per-parameter lookup tables applied before a pattern renders (`westeurope` → `we`, `development` → `dev`). Location codes follow the Azure Verified Modules `geo_code` convention. Unmapped values pass through unchanged.
- **`default_parameters`** — parameter defaults the provider's `parameters` override.

To add a resource type, add an entry under `abbreviations`, and a pattern under `patterns` only if the global or provider default does not suit it.

## Pattern Token Syntax

| Token | Meaning |
|---|---|
| `<PARAM>` | Required parameter — errors if missing |
| `<?PARAM;-%s>` | Optional parameter, dropped when unset, with its separator inside the token |
| `<PARAM;%02s>` | Printf-formatted parameter |
| `<TYPE>` | Resolved abbreviation for the resource (also `<ABBREVIATION>`) |
| `<NAMING_ID>` | The `naming_id`, falling back to the resource's `kind` |
| `<INDEX;%02s>` | Numeric index, shifted by `index_modifier` |
| `<UNIQUE_ID_n>` | First *n* characters of the `random_seed` UUID |

Put a separator **inside** an optional token (`<?SUBNAME;-%s>`), or a missing parameter leaves a stray separator behind. A literal `--` in a finished name is collapsed to `-`.

## Resolution Hierarchy

Abbreviations, first match winning:

1. `<type>::<naming_id>`
2. `<type>::<kind>`
3. `<type>::default`
4. `<type>`

Patterns, looked up under `patterns.<provider>`:

1. `<type>.<naming_id>`
2. `<type>.<kind>`
3. `<type>.default`
4. `<provider>.default`
5. `patterns.default`

Lower-case enforcement: `<provider>.<type pattern>` → `<provider>.default` → `default`. The bundled convention sets `default: true`, so names are lower-cased unless a convention says otherwise.

A key under a provider is matched as a **pattern** against the resource type, not as an exact name: `*` stands for any characters, and the pattern only has to appear *somewhere* in the type. So all three of these cover `Microsoft.Storage/storageAccounts`:

```yaml
enforce_lower_case:
  default: true
  Azure:
    "Microsoft.Storage/storageAccounts": false  # the exact type
    "Microsoft.Storage/*": false                # every type in the namespace
    "Microsoft.Storage": false                  # the same, since a prefix matches
    "*": false                                  # every Azure type
```

If several keys match, the first in alphabetical order wins — so prefer one unambiguous key per type over overlapping patterns.

A resource with no abbreviation anywhere, or a pattern whose required parameter is unset, fails the plan rather than rendering an empty segment.
